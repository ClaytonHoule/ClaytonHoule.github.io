Professional Self-Assessment

Completing the computer science program has changed the way I approach software development. When I first began working on the program, I focused on whether I could make programs that worked. Being new to computer programming, I needed to learn and grasp the fundamentals to succeed. As I progressed through the program, my perspective shifted to learning systems thinking and software design. I began thinking more about system design, how components interact, how software can be tested and maintained for future planning, what trade-offs are and when to apply them. This ePortfolio is designed to bring these concepts together and discuss how I use my skills to upgrade and enhance an earlier project.

While working in the program, full-stack development has been one of my favorite classes and projects to work on. Admittedly, I had little to no experience with UI/UX prior to this class. Full stack includes many of the subjects I enjoyed working on in the computer science program, such as databases, system architecture, and UI/UX design.

An important lesson I learned in the program is the value of collaboration during software development. I gained a lot of communicative experience from online discussion, reviewing instructor feedback, and email conversations I had with my professors. I was able to apply these to my projects, improving my projects in general, while also teaching me the importance of collaborating.

Planning has also been a major help throughout my courses. During my capstone, I drew up UML class designs to help visualize the flow I wanted my project to encompass. I would often reference online articles and examples for my capstone project as well, specifically when implementing Room database operations and making them asynchronous.

Other than software design, data structures and algorithms have changed how I approach programming problems. Toward the beginning of the program, I often focused on whether a solution worked without considering efficiency or speed. The courses covering algorithms taught me to focus more on time and space complexity when creating apps. I applied this to my capstone by implementing a low-stock filter with O(n) complexity and a merge sort algorithm with O(n log n) complexity.

Database development was especially important for my capstone. The original inventory app relied on an SQLite implementation. Although it worked for the class it was created in, I thought it was important to modernize the application by utilizing Android Room and a ViewModel structure. Besides the capstone, I also learned a lot from a previous full-stack development course. The project required me to work on both backend and frontend development for a travel website. I used tools such as MongoDB, MongoDB Compass, and Git throughout its development.

Another important section of the program was its emphasis on the software development life cycle, Waterfall and Agile/Scrum, and business/stakeholder communication. I practiced these concepts independently and through online interactions with other students. Many courses that focused on coding projects included assignments that required me to communicate with stakeholders, project managers, and other team members, reinforcing the importance of adjusting technical communication for different audiences.

Security has become increasingly important throughout my courses. In a previous Secure Coding course, I created several testing files using GTest frameworks and manual tests such as overflow and underflow tests. This course broadened my understanding of how tests are created, when they should be implemented, and how they are used throughout a project's life cycle. I applied these concepts to my capstone by adding asynchronous database operations and SHA-256 hashing for stored passwords.

The artifact enhancements in my ePortfolio work together to demonstrate growth across several areas of computer science. The software engineering enhancement focused on improving architecture and code organization as well as using Kotlin, the algorithms enhancement added a low-stock filter and merge sort algorithm that are efficient and appropriate for the app, and the database enhancement migrated inventory storage from SQLite to Room, modernizing data storage while improving reliability and security practices. These enhancements showcase how I applied what I learned to an application in a structured, measurable way.

The ePortfolio brings the whole picture together to demonstrate how my approach to computer science has developed. From creating programs that simply worked to designing software that is organized, testable, secure, and maintainable, the program helped shape my interests and taught me how to understand software fundamentally. These experiences have reinforced my interest in full-stack and app development, where I can continue working with system architecture, databases, and both backend logic and frontend design.

Software Design and Engineering

The first enhancement focused on modernizing the structure of the Android inventory application. Major changes included introducing Kotlin, a repository layer, and a ViewModel while moving application logic away from ActivityMain. These changes improved separation of responsibilities, maintainability, and the overall architecture of the application.

Software Design and Engineering Narrative

Algorithms and Data Structures

The second enhancement introduced algorithmic functionality for inventory management. A linear O(n) low-stock filter and an O(n log n) merge sort by quantity were implemented, integrated into the application, and supported with unit tests. A configurable low-stock threshold was also added.

Algorithms and Data Structures Narrative

Databases

The third enhancement migrated inventory persistence from the original SQLite implementation to Android Room. The final architecture uses a Room entity, DAO, database, repository, and ViewModel. Database operations were moved off the main UI thread, CRUD tests were added, and stored passwords were changed from plaintext storage to SHA-256 hashing.
